## 8. Атрибуты качества

В этом разделе сформулированы основные атрибуты качества, которые определяют архитектурное решения нашей системы. Для проекта выбраны несколько «глобальных» атрибутов (важны почти для всех подсистем) и несколько доменно‑специфичных.

### 8.1. Основные глобальные атрибуты качества

#### 8.1.1. Масштабируемость

**Определение:** способность системы обрабатывать рост числа пользователей, тренировок, социальных событий и интеграций, сохраняя приемлемое время отклика и стабильность.

**Почему важна:**

- Массовые челленджи, корпоративные соревнования и глобальные кампании могут создавать пик нагрузки по событиям и чтению данных.
- Социальная лента, рейтинги и уведомления потенциально масштабируются как $O(n)$ от числа активных пользователей.

**Ключевые решения:**

- Микросервисная / модульная архитектура с разделением по доменам (Community, Training, Commerce и т.д.).
- Использование асинхронного обмена через шину событий (Event Bus) между сервисами.
- Возможность горизонтального масштабирования критичных сервисов (Training, Feed, Challenges, Notifications).
- Кэширование горячих данных (ленты, агрегатов, лидербордов) и продуманные индексы в БД.

#### 8.1.2. Надёжность и доступность

**Определение:** способность системы оставаться работоспособной и корректно сохранять данные даже при частичных отказах компонентов и инфраструктуры.

**Почему важна:**

- Потеря тренировок и результатов челленджей напрямую бьёт по доверию и удержанию.
- Приложение используется в «живых» тренировках и событиях; недоступность в момент активности воспринимается очень болезненно.

**Ключевые решения:**

- Репликация данных и отказоустойчивые кластеры для критичных хранилищ.
- Разделение критичных и вторичных функций (graceful degradation: если недоступен commerce, тренировки и челленджи должны работать).
- Офлайн‑буферизация и надёжная синхронизация тренировок при восстановлении связи.
- Механизмы повторной обработки событий (idempotent‑операции, уникальные идентификаторы тренировок и событий).

#### 8.1.3. Безопасность и конфиденциальность (Security \& Privacy)

**Определение:** защита данных и сервисов от несанкционированного доступа, утечек и злоупотреблений, при соблюдении требований регуляторов и ожиданий пользователей.

**Почему важна:**

- Обрабатываются чувствительные данные: геолокация, здоровье, социальные связи, история покупок.
- Есть риск деанонимизации маршрутов и привычек пользователя (место проживания, работы и т.п.).

**Ключевые решения:**

- Централизованный контур Identity \& Security (SSO, IAM), строгая аутентификация и авторизация.
- Шифрование данных в транзите и в покое, минимизация хранимых персональных и health‑данных.
- Явные экраны согласия (consent), гибкие настройки приватности: видимость профиля, тренировок, маршрутов, участия в рейтингах.
- Журналирование доступа к критичным данным, регулярные security‑проверки и обновления.

#### 8.1.4. Наблюдаемость (Observability)

**Определение:** степень, в которой внутреннее состояние системы можно понять по её внешним сигналам (логи, метрики, трассировки).

**Почему важна:**

- Архитектура распределённая, с несколькими доменами и внешними интеграциями; без наблюдаемости сложно диагностировать проблемы производительности и отказов.
- Критичные сценарии (челленджи, массовые ивенты, рассылки уведомлений) требуют понимания, где именно возникают узкие места.

**Ключевые решения:**

- Единый стек observability (логи, метрики, traces) для всех сервисов, API Gateway и интеграций.
- Корреляция запросов по trace‑ID от мобильного клиента до backend‑сервисов и внешних систем.
- Набор бизнес‑метрик: количество тренингов, участие в челленджах, успешные/ошибочные синхронизации с устройствами, задержки отправки уведомлений.
- Алёрты по SLA (доступность, время отклика ключевых API, задержка событий, ошибки в интеграциях).


### 8.2. Дополнительные важные атрибуты

#### 8.2.1. Производительность (Performance)

**Определение:** время отклика и пропускная способность системы при типичных и пиковых нагрузках.

**Примеры требований:**

- Время загрузки главного экрана и ленты — миллисекунды/единицы секунд.
- Создание тренировки и отображение экрана результата — без заметных задержек для пользователя.
- Построение базовых рейтинг‑таблиц и выдача прогресса по плану — в пределах разумного UX.

**Основные подходы:**

- Оптимизация запросов к БД, использование агрегатов и кэшей вместо тяжёлых онлайн‑подсчётов.
- Асинхронная обработка тяжёлых операций (пересчёты, рассылка уведомлений, аналитика).
- Разделение «online‑запросов» и фоновой аналитики.


#### 8.2.2. Расширяемость и модифицируемость (Extensibility / Modifiability)

**Определение:** возможность добавлять новые фичи и интеграции с минимальными изменениями существующего кода и архитектуры.

**Почему важна:**

- Бизнес хочет экспериментировать с новыми типами челленджей, промо, планов, интеграций с устройствами и B2B‑сценариями.
- Нельзя допустить, чтобы каждая новая идея требовала серьёзной перестройки системы.

**Основные подходы:**

- Доменно‑ориентированное разбиение (bounded contexts), чёткие границы сервисов.
- Использование событийной модели для loosely coupled взаимодействий (новое потребление событий без изменения их источника).
- Расширяемые модели данных (осторожное использование схем с опциональными полями, версионирование контрактов).

#### 8.2.3. Юзабилити и пользовательский опыт (Usability / UX)

**Определение:** удобство и понятность интерфейса, лёгкость выполнения ключевых сценариев.

**Почему важна:**

- Аудитория массовая, с разным уровнем цифровых навыков; сложный UX ведёт к низкому adoption.
- Пользователь не готов «разбираться», как запустить тренировку или присоединиться к челленджу — это должно быть интуитивно.

**Основные подходы:**

- Простые, линейные сценарии для ключевых действий (старт тренировки, вступление в челлендж, просмотр прогресса).
- Согласованность интерфейсов между модулями (community, планы, commerce).
- Постепенное раскрытие сложности (onboarding, подсказки, контекстные хелп‑элементы).

### 8.3. Привязка атрибутов качества к подсистемам

| Подсистема / домен | Ключевые атрибуты качества |
| :-- | :-- |
| Identity \& Security | Безопасность, конфиденциальность, надёжность |
| Training Service | Надёжность, производительность, наблюдаемость |
| Training Plans \& Rules Engine | Производительность, модифицируемость, расширяемость |
| Community / Feed / Challenges | Масштабируемость, производительность, наблюдаемость, приватность |
| Commerce \& Catalog / Gear | Производительность, надёжность, интегрируемость, расширяемость |
| Integrations (devices, B2B) | Надёжность, масштабируемость, наблюдаемость |
| Event Bus | Масштабируемость, надёжность, наблюдаемость |
| Analytics / DWH | Масштабируемость, производительность (батч/stream), расширяемость |
| Observability Stack | Наблюдаемость, поддерживаемость, операбельность |
